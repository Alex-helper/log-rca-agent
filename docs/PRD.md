# PRD — 日志根因定位 Agent（MCP）

## 产品定位

面向运维 / 值班 / SRE 的**告警→根因报告**专用 Agent：用户粘贴一条告警事件，系统通过 MCP 工具拉取/检索日志、多步推理，在约 3 分钟内输出结构化根因报告（根因、影响范围、修复建议）。

一句话 USP：**不是聊天机器人，而是「告警驱动的可观测排障流水线」**。

## 用户画像与痛点

| 角色 | 痛点 |
|------|------|
| 值班工程师 | 微服务日志散落多服务，手动 grep / 跳转耗时，MTTR 长 |
| SRE | 需要可复现的排障路径与证据链，而非口头猜测 |
| 面试官视角（作品集） | 要看到 Agent + MCP + 可观测 + 自研改进，而非 CRUD |

**现状缺口**：通用问答 / 客服助手无法对接日志工具链；纯检索无推理；纯 LLM 无工具调用易幻觉。

## MVP 做什么

1. 告警输入（文本 / 结构化 JSON）
2. Agent（ReAct）多步调用 MCP 工具：服务列表、按 trace/service 查日志、时间窗聚合
3. SSE 流式展示推理轨迹（Thought / Action / Observation）
4. 结构化报告：根因假设、证据片段、影响范围、修复建议、置信度说明
5. 本地样例日志包（可 docker-compose 一键起）
6. 基线 vs 改进评测：结构化摘要、多级缓存对 Token / 延迟 / 外部调用次数的影响

## 功能黑名单（禁止）

- 通用问答助手 / 闲聊 / 智能客服 / FAQ 知识库聊天
- 「Chat with PDF」万能壳
- 无告警上下文的开放域对话
- 编造线上 DAU / 准确率；无测评集不写结果数字
- 微调模型（本轮范围关闭）

## 核心用户旅程

1. 打开工作台 → 粘贴告警（或选样例）
2. 点击「定位根因」→ 右侧流式展示 Agent 步骤
3. 结束后阅读报告；可复制 Markdown / JSON
4. （可选）查看本次调用指标：Token、耗时、缓存命中、工具调用次数

## 技术方案（预确认）

| 层 | 选型 | 说明 |
|----|------|------|
| 前端 | React + Vite | 告警输入、SSE 推理流、报告区 |
| 后端 | FastAPI | Agent 编排、SSE、评测 API |
| AI | DeepSeek `deepseek-chat` | 国内 OpenAI-compatible；重试+超时 |
| 协议 | MCP（Model Context Protocol） | 日志工具以 MCP Server 暴露 |
| Agent | ReAct | Thought→Action→Observation 循环 |
| 可观测 | OpenTelemetry | trace 贯穿请求与工具调用 |
| 自研改进 | 结构化日志摘要 + 多级缓存 | 降 Token / 延迟 / 重复工具调用 |
| 部署 | 优先**免费国内可访问**：Sealos 免费额度 / 魔搭创空间 / 本机 + Cloudflare Tunnel；备选阿里云轻量 | **禁止** HF Spaces / Vercel / Railway / Streamlit Cloud 作为主 Demo |

## 主要风险

| 风险 | 应对 |
|------|------|
| 真实集群不可用 | 内置合成微服务日志 fixture |
| Agent 跑飞 | 最大步数、工具白名单、超时 |
| Demo 成本 | 免费平台优先；Key 仅服务端；缓存降调用 |
| 幻觉根因 | 报告必须挂证据 snippet；无证据标「假设」 |

## 验收标准（可测试）

1. 给定样例告警，3 分钟内（本地）产出含根因/影响/建议的报告。
2. 推理过程可见至少一次 MCP 工具调用。
3. 产品文案与交互不出现客服/闲聊入口。
4. `docker-compose up` 可本地启动前后端与样例数据。
5. 推理主路径模型为 DeepSeek `deepseek-chat`。
